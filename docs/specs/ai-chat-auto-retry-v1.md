# AI 对话自动重试池 V1

## 目标

当任务绑定的 Codex 对话因为单行 JSONL 超过 1 MiB 而失败时，Taskboard 将失败记录持久化到“待重试”池，并在同一对话中自动续跑，避免用户手动复制上下文或新建任务。

## 触发范围

仅在同时满足以下条件时入池：

- 运行状态为 `failed`，稳定错误码为 `CODEX_JSONL_LINE_TOO_LARGE`；
- 对话绑定了未归档、状态为 `in_progress` 的任务；
- 运行不是服务器编排的 planner/worker dispatch，也不是某次自动重试；
- 本次输入没有附件；
- 对话未归档，且 sandbox 不是 `danger-full-access`。

其他错误仍保留原来的人工“重试上一条消息”能力，不会被自动重放。

服务器编排的 planner/worker dispatch 不进入本自动重试池。编排子任务的失败或中断由 handoff 协调；当 handoff 已停止或失败后，用户可以在任务绑定对话点击“继续处理”，由服务器保留旧历史并创建新的 worker attempt。这个人工恢复入口与本规格的 JSONL 自动重试互不替代。

## 状态与时序

重试任务持久化在 `ai_chat_retry_jobs`：

1. 原运行失败后进入 `pending`，首次等待 30 秒；
2. 到期后以 CAS 方式领取为 `claimed`，在原 `thread_id` 创建新运行并进入 `running`；
3. 成功后进入 `succeeded`；再次失败则等待 2 分钟后继续；
4. 最多自动尝试 2 次，仍失败进入 `exhausted`，界面显示“待人工处理”；
5. 服务重启时，未完成的 `claimed`/`running` 状态会按数据库中的运行终态恢复，不会丢失或无限重放。

数据库用 `source_run_id` 唯一约束保证同一失败只入池一次，并限制同一对话只能有一个活跃重试任务。

## 恢复消息

自动重试会明确要求 Codex：

- 回读已有状态，从最后一个可确认点继续；
- 不读取或输出整份 JSONL、大型日志或大文件；
- 使用 `rg`、`head`、字段筛选与输出上限；
- 外部写入结果不确定时先回读，不盲目重放。

## 界面

AI 对话历史新增“待重试”筛选页。列表与当前对话会展示：

- `待重试`：等待下一次尝试；
- `自动重试 x/2`：正在执行；
- `待人工处理 · 已重试 2/2`：自动尝试已耗尽。

## 回滚

停止创建 `AiRetryCoordinator` 即可禁用自动执行；已有重试表和 `retry_job_id` 字段可以保留为惰性数据，不影响原有对话与手动重试流程。回滚时不得删除重试表，以免丢失诊断记录。
