# 多项目聚合看板版本规划

## 产品概述

- 核心定位：允许用户在项目切换菜单中同时选择多个项目，并在同一议题看板中聚合查看这些项目的任务。
- 核心价值：减少在多个项目之间反复切换，快速看清跨项目的积压、待开发、进行中、审核中和待解决事项。
- 目标用户：同时维护多个 Codex 项目、收件箱或计划项目的 Taskboard 用户。
- 已排除问题：界面中曾出现两个 `Obsidian Vault`，是当时同时打开了两个项目实例；用户已关闭其中一个，本需求不处理项目去重。

## 当前真实操作路径

当前路径是严格的单项目模型：

1. 用户在 `web/src/App.tsx` 的项目菜单点击一个 `menuitemradio`。
2. `changeProject(projectId)` 把唯一的 `selectedProjectId` 写入 React 状态、`taskboard.last-project` 和 URL 的 `project` 参数。
3. `refreshTasks(selectedProjectId)` 调用 `web/src/api.ts` 的 `listTasks(projectId)`。
4. 前端请求 `GET /api/tasks?projectId=<id>&archived=false`；`server/app.mjs` 校验单个 `projectId`，`server/database.mjs` 用 `project_id = ?` 查询任务。
5. 返回任务按状态分列显示；卡片当前不显示项目名，因为单项目上下文已经隐含了来源。

现有本地和 Cloud API 在不传 `projectId` 时都能返回全部未归档任务。因此 V0.1 可复用现有接口，在前端按已选项目集合过滤，不需要先修改数据库结构或任务归属模型。

## 产品边界

### 必须保持的事实

- 一张任务仍只属于一个 `projectId`；“多选”只改变看板视图，不改变任务归属。
- 单项目模式继续保留现有 URL、记忆、项目自动化、节点模式、工作区上下文和新建任务行为。
- 多项目模式中的卡片必须显示所属项目，否则同名任务和跨项目排序无法辨认。
- 项目选择为空时返回项目首页，不引入“隐式全选”。

### 最可能失败的地方

现有 `sortOrder` 只在单个项目内有意义。直接把多个项目的任务混在一个列表后允许拖拽，会拿其他项目的相邻卡片计算排序值，导致回到单项目看板时顺序异常。

替代方案：V0.1 的多项目聚合看板层只负责查看、搜索、筛选和打开任务；隐藏新建入口并禁用看板拖拽、快捷移动和列内排序。用户打开某张卡片后，进入该任务所属项目的单项目详情上下文，因此现有详情编辑能力仍可使用；关闭详情时恢复此前的多项目选择。单项目看板保持全部现有编辑能力。

## 核心需求清单

| 优先级 | 需求 | 说明 |
|---|---|---|
| P0 | 项目菜单支持复选 | 菜单保持打开，可连续勾选或取消多个项目 |
| P0 | 聚合加载任务 | 只展示已选项目的未归档任务 |
| P0 | 卡片显示项目 | 仅多项目模式显示项目名称或短标识 |
| P0 | 搜索与筛选覆盖聚合结果 | 复用现有搜索、标签、负责人、优先级等筛选 |
| P0 | 详情路由保留聚合集合 | 打开任务时聚焦其所属项目，返回时恢复原多项目视图 |
| P0 | 多项目模式禁止歧义写入 | 暂停拖拽排序、列快捷移动、项目自动化、节点模式和直接新建 |
| P1 | 多项目中新建任务 | 新建前明确选择唯一目标项目 |
| P1 | 多项目中安全移动状态 | 只依据任务所属项目的同状态任务计算 `sortOrder` |
| P1 | 记住上次项目组合 | 本地保存稳定、去重后的项目 ID 集合 |
| P2 | 服务端多项目过滤 | 数据量增大后支持 `projectIds`，避免读取全部任务 |
| P2 | 收藏常用组合 | 例如“全部工作项目”“收件箱 + 主项目” |

## 版本规划路线图

### V0.1 MVP：多项目聚合查看

目标：验证用户能否通过一次多选，看清多个项目的任务分布，而不破坏单项目操作。

功能清单：

1. 将项目菜单从 `menuitemradio` 改为多选语义，已选项目显示复选状态。
2. 引入 `selectedProjectIds` 视图状态；单选时仍显示项目名，多选时显示“已选 N 个项目”。
3. 多选后读取全部未归档任务，并按 `selectedProjectIds` 在前端过滤。
4. 任务卡在多项目模式显示所属项目名称。
5. 搜索、任务筛选、状态列计数和空状态基于聚合后的任务集合工作。
6. 多项目详情路由同时保留项目集合与当前任务所属项目；详情页复用该项目现有编辑能力，关闭详情后恢复原聚合视图。
7. 多项目模式隐藏项目自动化和节点模式；禁用新建、拖拽、快捷移动和列排序，并给出简短说明。
8. 单项目模式行为保持不变。

不做：

- 不让一张任务同时属于多个项目。
- 不在多项目模式新建任务。
- 不在多项目看板层调整任务状态或排序；进入单任务详情后的现有编辑不属于该限制。
- 不增加服务端 `projectIds` 查询参数。
- 不创建、保存或分享项目组合。

验证点：

1. 勾选两个项目后，两边的任务同时出现，列计数正确，每张卡能辨认来源。
2. 取消其中一个项目后，另一项目的任务立即从聚合结果消失。
3. 搜索或筛选只作用于当前已选项目集合。
4. 打开任一项目的任务详情后使用正确的单项目上下文，返回时仍保留原选择集合。
5. 多项目模式无法触发含糊的任务创建、项目自动化、节点模式或跨项目排序。
6. 回到单项目模式后，原有新建、拖拽、自动化和节点模式不受影响。

工作量：中。主要集中在 `App.tsx` 的状态/路由拆分、项目菜单语义、卡片来源标识和多项目只读边界。

### V0.2：多项目安全操作

目标：让聚合看板从“统一查看”升级为“统一处理”，同时保持任务唯一归属。

功能清单：

1. 新建任务时先选择唯一目标项目，再打开现有编辑器。
2. 允许跨状态移动，但排序邻居只从任务所属项目内计算。
3. 允许同项目任务在聚合看板内排序；跨项目卡片之间不表达持久排序关系。
4. 任务改派项目后保留当前聚合视图，并按新归属决定卡片是否继续显示。
5. 多项目视图使用一套独立的列显示偏好，不覆盖任何单项目偏好。

不做：

- 不批量修改多个项目的自动化。
- 不把多个项目合并为一个工作区或节点画布。
- 不允许任务具有多个项目归属。

验证点：

1. 从聚合视图新建任务时必须选择项目，创建后只增加该项目计数。
2. 移动一个项目的任务不会改变其他项目的 `sortOrder`。
3. 返回单项目看板后，任务顺序与状态正确。

工作量：中到大。关键是把任务状态移动与排序从“当前看板集合”改为“任务所属项目集合”。

### V1.0：可复用的跨项目工作视图

目标：在任务量和项目数增加后，提供稳定、可分享、可恢复的多项目视图。

功能清单：

1. 本地和 Cloud API 支持显式的多项目过滤参数，并保持单项目参数兼容。
2. URL 可分享当前项目组合、搜索和筛选状态。
3. 支持保存、命名和收藏常用项目组合。
4. 增加“全选当前分组”“清空选择”和键盘可访问性。
5. 对大量任务增加加载、错误提示和性能优化。

验证点：

1. 分享链接能恢复相同项目组合与筛选条件。
2. 本地和 Cloud 模式返回一致结果。
3. 项目或任务数量增加后，不需要读取与视图无关的任务。
4. 键盘与读屏可以完成项目增删选择并理解当前选择数量。

工作量：大。涉及 API 合同、本地与 Cloud 双实现、组合持久化和完整交互打磨。

## V0.1 建议实现面

| 文件 | 规划改动 |
|---|---|
| `web/src/App.tsx` | 拆分单项目上下文与多项目视图状态；聚合加载、菜单切换、标题、路由及只读能力判断 |
| `web/src/api.ts` | 允许 `listTasks` 在不传 `projectId` 时复用现有“全部任务”接口 |
| `web/src/issueRoute.ts` | 保留项目集合参数，并继续用任务项目解析详情 |
| `web/src/components/TaskCard.tsx` | 多项目模式显示项目标识并关闭移动入口 |
| `web/src/components/BoardColumn.tsx` | 多项目模式关闭新建和拖拽排序能力 |
| `web/src/styles.css` | 复选菜单、聚合标题、项目标识和禁用说明样式 |

V0.1 不计划修改 `server/database.mjs`、`server/app.mjs` 或 `cloud/src/index.mjs`；现有无 `projectId` 的列表能力足以验证核心价值。

## 验收边界

- “完成”只表示多项目聚合查看的真实路径可用，不代表 V0.2 的跨项目操作或 V1.0 的可分享组合已经完成。
- 实现后必须在真实界面证明：菜单勾选 → 选择集合变化 → 任务请求与过滤 → 聚合卡片出现 → 打开详情 → 返回后集合保留。
- 本规划不改动任何任务状态、飞书数据、自动化配置或 Production 状态。

## 下一步行动

用户确认 V0.1 边界后，按仓库规则先证明现有真实操作路径，再只实现 V0.1 的直接主路径。
