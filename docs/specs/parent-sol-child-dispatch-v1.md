# 父任务 planner 子卡派发门控 V1

## 背景

此前，有顶层“主任务”父级的既有子卡被单独拖入“待开发”时，会作为普通任务直接创建 Terra Max + Fast 会话。父任务 Sol 可能尚未启动或已经失败，导致子卡绕过统一编排。

## 决策

- 所有任务进入 `todo` 后仍先经过持久化 readiness review。
- 独立普通任务继续使用 `gpt-5.6-sol / xhigh / read-only` 做需求完整性审核。
- 子卡的父级同时满足“带 `主任务` 标签、无父级、未归档”时，readiness review 升级为父任务上下文的 `gpt-5.6-sol / max / read-only` 派发审核。
- 派发审核输入必须包含父任务目标和用户评论、当前子任务、同级任务状态以及阻塞依赖。
- 只有审核返回 `ready` 后，服务器才复用现有入口创建开发会话；新会话默认 `gpt-5.6-luna / max / priority / workspace-write`，用户可在空闲时切换模型、推理强度和服务等级。
- 审核返回 `needs_confirmation` 或失败时，任务进入 `blocked`，不启动开发 worker。

派发审核使用子任务已有的 `task_readiness_reviews` 持久化状态，不新增数据库表。审核对话独立存在，避免多个子卡争用同一个父任务 planner 对话；它携带完整父任务上下文，并在标题和任务详情中明确显示“父任务 planner 派发审核”。新对话以 Sol 为默认模型，但该名称不作为模型锁；用户在会话空闲时可以切换模型、推理强度和服务等级。

## 保持不变

- 顶层主任务审核通过后，仍由主任务 planner 生成或协调正式编排。
- 由正式 planner 计划创建的 worker 与 handoff 流程保持不变。
- 普通独立任务的审核和开发流程保持不变。
- 已经运行的历史开发会话不回溯中断，也不批量改写模型。

## 回滚

撤销 `TaskReadinessCoordinator` 的父任务 profile 和前端动态文案即可恢复旧行为；没有数据迁移或清理步骤。
