# 任务状态说明

本文说明任务面板中每个状态的含义、负责人、进入后的系统后果，以及 AI 是否会介入。

AI 的完整触发规则见 [AI 介入与触发事件](ai-intervention-triggers.md)。

## 状态总览

主流程：

```text
积压事项 → 待开发 → 进行中 → 审核中 → 待复盘 → 完成
                         └─ 返工意见 → 待开发 → Sol 审核 → 进行中
```

异常与终止状态：

```text
任意活动阶段 → 待解决
任意未归档阶段 → 已取消
```

界面允许跨阶段直接切换状态。状态变化本身不等于对应工作已经真实发生；例如，直接移动到进行中不会自动产生开发结果，直接移动到完成也不会补做验收或复盘。

## 快速参考

| 状态 | 内部值 | 表示什么 | 默认下一责任人 | AI 后果 |
| --- | --- | --- | --- | --- |
| 积压事项 | `backlog` | 已记录，暂不执行 | 任务负责人或用户 | 不启动审核或开发 |
| 待开发 | `todo` | 准备进入执行前审核 | Codex Agent 或任务负责人 | 负责人为 Codex Agent 时触发 Sol readiness |
| 进行中 | `in_progress` | 正在实现或返工 | Codex Agent | 直接移动到此状态不会自动启动 AI |
| 审核中 | `in_review` | 已有交付，等待用户验收 | 用户 | 普通任务不自动启动 AI；编排子任务会产生 handoff |
| 待复盘 | `pending_retrospective` | 交付已接受，尚未完成复盘 | 用户或复盘负责人 | 不自动启动 AI |
| 完成 | `done` | 验收和复盘均已闭合，或复盘被明确免除 | 无 | 不自动启动 AI |
| 待解决 | `blocked` | 当前存在阻塞，不能继续 | 能解除阻塞的人 | readiness 不通过或启动失败时可能自动进入；明确复审可再触发 Sol |
| 已取消 | `canceled` | 当前任务不再继续，但仍保留记录 | 无 | 普通任务不启动 AI；编排子任务会产生取消 handoff |

## 各状态的完整说明

### 积压事项 `backlog`

用途：保存需求、想法和尚未决定启动的工作。

进入后的后果：

- 不启动需求审核。
- 不启动开发对话。
- 可以修改、补充评论、设置负责人和开发上下文。
- 详情页允许在此状态重新分配项目；服务器也允许已完成任务重新分配项目。

离开条件：用户或有权操作的 Agent 明确决定推进。将任务移动到待开发后，是否触发 AI 取决于负责人。

### 待开发 `todo`

用途：表示任务准备进入执行，但在 Codex Agent 接手时仍需先通过需求完整性审核。

进入后的后果：

- 负责人是 Codex Agent：启动 Sol 只读审核。
- 负责人不是 Codex Agent：只改变状态，不自动启动审核。
- 从审核中发起返工时，任务带有 `reworkRound`，Sol 会优先审核该轮返工评论；该评论在 AI 输入中单独出现一次，不再与普通评论历史重复。手写意见和采纳的 AI 审核意见使用同一路径。
- 顶层主任务通过审核后进入 Sol planner。
- 普通任务或手动移动到待开发的子任务通过审核后启动开发 worker；新对话默认 Luna，既有对话沿用当前模型。

会重新审核的修改：标题、描述、标签。

不会重新审核的修改：优先级、负责人、截止时间、重复设置、分支/worktree。

注意：只把一个已经处于待开发的任务改派给 Codex Agent，不会单独触发审核。需要再次改变状态，或修改标题、描述、标签，才会产生当前代码监听的事件。

### 进行中 `in_progress`

用途：表示 Agent 或负责人正在实现、验证或返工。

进入后的后果：

- 直接手动移动到进行中只修改状态，不会自动创建开发对话或交付结果。
- 返工任务只有在本轮 Sol 审核通过并实际启动开发 worker 后才进入进行中；提交意见本身不会直接开工。
- 主任务编排调度开发 worker 时，服务器会自动把子任务推进到进行中。
- 顶层主任务审核通过时，如果已有失败的 planner 编排，服务器会按 readiness 轮次幂等恢复原 planner 线程；不会要求用户再发布一条继续评论。
- 主任务计划精确引用同项目、未归档且已经属于该主任务的既有子任务时，服务器原位纳管并保留状态；已有审核中、待解决或已取消状态先进入 handoff 协调，不会重复创建或直接重跑。
- 项目自动开发只认领负责人为 Codex Agent 且 readiness 为 `ready` 的待开发任务，然后将其改为进行中。

离开条件：

- 实现和自验证完成后进入审核中。
- 无法继续时进入待解决。
- 不再继续时进入已取消。

### 审核中 `in_review`

用途：表示已有交付说明或开发结果，等待用户验收。它不是完成状态。

用户可执行的主要动作：

- 验收通过后移动到待复盘。
- 点击“提交返工并重新审核”，将评论、附件和内嵌图片登记为新的返工轮次，任务回到待开发并启动 Sol 审核。
- AI 交付审核评论可点击“采纳意见并发起返工”；系统会复制该反馈为一条用户返工评论，再进入相同审核链路。
- 点击“发布并重新审核”，启动 Sol X-High 只读交付复核；任务保持审核中，完成后新增审核评论。
- “仅发布”只记录评论，不启动 AI。

界面会在任务卡、详情阶段和对应评论上显示 `↩ 返工 #N`。任务进入待复盘、完成或已取消时清除当前返工标识，历史返工评论仍保留各自轮次。

详情页把当前主交付集中显示在“开发结果待验收”区域；活动记录中的同一条评论只保留提交时间和来源，避免重复展示验收正文。同一个介入原因命中多个介入视图时，详情页合并为一项，任务列表的各视图归类保持不变。

主任务编排的特殊后果：编排子任务进入审核中时，服务器会创建 completed handoff 并唤醒父任务 Sol。完整 handoff 保存在专用表；新评论只写有限展示快照，不重复保存同一 `summary`。父任务 Sol 可以确认交付、要求补证据或继续协调。旧 handoff 评论保持原样。

### 待复盘 `pending_retrospective`

用途：表示用户已经接受交付或确认已上线，但复盘尚未完成。

进入条件：必须有用户明确验收或上线确认。Codex 自验证、测试通过、PR 可合并或部署 `READY` 都不足以自动进入此状态。

进入后的后果：

- 记录 `deliveredAt`。
- 在数据库中使用 `status = done` 与 `retrospective_status = pending` 组合存储，对外仍显示为 `pending_retrospective`。
- 不自动启动复盘 AI，也不等于最终完成。

离开条件：复盘完成，或用户明确免除复盘，才能进入完成。

### 完成 `done`

用途：表示交付、验收和复盘全部闭合，或者用户明确免除复盘。

进入后的后果：

- 不启动 AI。
- 任务仍可重新打开到其他状态。
- 服务器允许完成任务重新分配项目。
- 不进入顶部“待我解决 / 待我跟进 / 待我评论”视图。
- 完成不等于归档。任务仍会显示在活动面板，除非另行归档或隐藏对应列。

不应直接把“开发结束”当作完成。正常流程是开发结束进入审核中，用户验收后进入待复盘，最后才完成。

### 待解决 `blocked`

用途：表示存在阻塞，当前不能继续。

常见进入原因：

- Sol 判断需求信息不足。
- 需求审核运行失败。
- 需求审核通过，但普通任务开发对话启动失败。
- 编排中的开发 worker 失败或中断。
- 用户或 Agent 手动标记阻塞。

进入后的后果：

- 系统不会记忆或推断解除阻塞后应该回到哪个阶段。
- 如果 readiness 状态为 `awaiting_input` 或 `failed`，用户点击“发布并重新审核”会再次启动 Sol。
- 重新审核进入 `running` 后，任务可以暂时保留在待解决，直到本轮结论生成；卡片显示“Agent 审核中 · 当前无需你处理”，并退出“待我解决 / 待我跟进 / 待我评论”视图。planner、worker、自动重试、handoff 协调或主任务下的子任务仍有当前活动时，卡片同样显示对应的 Agent 进度，而不是把旧失败冒充当前人工待办。较早的失败仍保留在活动记录；只有当前流程重新明确等待用户输入或失败且没有更新的 Agent 活动接管时，才再次提示用户。
- 编排子任务进入待解决时会产生 failed handoff，父任务 Sol 可决定继续、修订、创建修复任务或停止。
- 如果编排 handoff 已停止或协调失败，用户可在对应任务对话点击“继续处理”。服务器保留旧 handoff，并在同一开发对话按当前模型创建新的 worker attempt；启动后任务进入进行中，本次结果另建新 handoff。

解除方式取决于阻塞来源。不要仅把状态拖回进行中来假装问题已经解决；若阻塞来自需求审核，应通过明确的复审动作留下可追踪证据。

### 已取消 `canceled`

用途：表示工作不再继续，但保留任务和历史记录。

进入后的后果：

- 不会归档任务。
- 普通任务不会启动 AI。
- 编排子任务会创建 canceled handoff，让父任务 Sol 记录或处理取消。
- 不进入顶部“待我解决 / 待我跟进 / 待我评论”视图。
- 之后仍可跨阶段重新打开。

取消和归档不同：取消是业务状态；归档是生命周期操作。

## 推荐的正常流转规则

| 当前阶段 | 推荐操作 | 目标阶段 | 必要证据 |
| --- | --- | --- | --- |
| 积压事项 | 明确启动任务 | 待开发 | 任务范围和负责人已确定 |
| 待开发 | Sol 审核通过 | 进行中 | readiness 为 `ready`，开发对话已实际启动 |
| 进行中 | 完成实现和自验证 | 审核中 | 交付评论、验证结果、未验证项和用户验收步骤 |
| 审核中 | 提交或采纳返工意见 | 待开发 | 新的返工轮次及完整返工评论 |
| 审核中 | 用户明确接受交付或确认上线 | 待复盘 | 用户确认记录 |
| 待复盘 | 完成复盘或用户明确免除 | 完成 | 复盘结论或免除记录 |

异常流转：

- 信息不足或执行失败：进入待解决。
- 明确不再继续：进入已取消。
- 修复待解决事项后，回到哪个阶段应由实际阻塞来源决定。

## 状态和 AI 执行不是同一件事

判断 AI 是否真实介入，不能只看任务状态。至少需要同时检查：

- `readinessReview` 是否存在、处于哪一轮和什么状态。
- 是否存在对应的 AI thread 和 run。
- 是否存在 planner/worker dispatch。
- 主任务是否有 orchestration child 和 handoff。
- 评论中是否有审核结论、交付摘要或失败记录。

典型误判：

- 在待开发，不代表 Sol 已经启动。
- 在进行中，不代表开发 worker 正在运行。
- 在审核中，不代表交付已经通过。
- 在待复盘，不代表任务已经最终完成。
- 存在 planner 对话，不代表 Sol run 成功执行。

## 状态以外的生命周期操作

### 归档与恢复

- 归档任务后，任务变为只读。
- 任务绑定的 AI 对话随任务归档和恢复。
- 顶层主任务存在活跃子任务执行、运行或未处理 handoff 时，归档可能被拒绝。
- 归档不是完成，恢复也不会自动启动 AI。

### 项目重新分配

- 服务器只允许积压事项或完成任务重新分配项目。
- 详情页当前只在积压事项显示项目重新分配入口。
- 重新分配项目不会自动启动 AI。

### 重复任务

复制任务会创建新任务记录，但不会继承原任务的开发上下文。新任务是否触发 AI 取决于复制后的初始状态和负责人。
